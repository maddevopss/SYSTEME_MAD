Développement logiciel

Règle d’or

Nous développons des solutions durables, pas seulement du code.

---

Pourquoi ce chapitre existe

Le développement logiciel constitue l’un des moyens que nous utilisons pour résoudre les problématiques des entreprises.

Notre objectif n’est jamais d’écrire le plus de code possible.

Notre objectif est de créer une solution simple, fiable et évolutive qui répond à un besoin réel.

Le code n’est qu’un outil au service de cette mission.

---

Notre vision

Nous croyons qu’un bon développement logiciel est avant tout un travail de réflexion.

Avant d’écrire une ligne de code, nous cherchons à comprendre :

* le problème;
* les utilisateurs;
* les contraintes;
* les objectifs;
* les impacts.

Nous développons seulement lorsque la solution est suffisamment comprise.

---

Nos principes

Chaque développement doit respecter les principes suivants.

Simplicité

Nous privilégions les solutions les plus simples capables de répondre au besoin.

La simplicité facilite la compréhension, la maintenance et l’évolution d’une solution.

---

Lisibilité

Le code doit être compris rapidement.

Nous privilégions des noms explicites, une structure claire et des responsabilités bien définies.

Nous écrivons du code que nous serons heureux de relire dans plusieurs années.

---

Progression

Nous développons progressivement.

Chaque étape produit un résultat concret pouvant être validé.

Les petites évolutions réduisent les risques et facilitent les ajustements.

---

Robustesse

Nous anticipons les erreurs.

Une application doit gérer les situations imprévues avec élégance et fournir des messages compréhensibles.

Une erreur bien gérée inspire davantage confiance qu’une erreur cachée.

---

Documentation

Les décisions importantes doivent être documentées.

La documentation facilite la maintenance, le transfert de connaissances et l’évolution d’un projet.

---

Refactoring

Nous améliorons continuellement notre code.

Le refactoring est une activité normale du développement.

Il ne s’agit pas de réécrire pour le plaisir, mais de préserver la qualité au fil de l’évolution du projet.

---

Notre responsabilité

Nous sommes responsables de la qualité du code que nous produisons.

Cette responsabilité comprend :

* la sécurité;
* la performance;
* la stabilité;
* la maintenabilité;
* la compréhension du code;
* la protection des données.

---

Notre définition d’un bon code

Un bon code est un code :

* simple à comprendre;
* simple à modifier;
* simple à tester;
* simple à documenter.

Nous privilégions toujours la clarté à l’ingéniosité.

---

Ce que nous faisons toujours

✔ Comprendre avant de développer.

✔ Développer progressivement.

✔ Documenter les décisions importantes.

✔ Corriger les causes plutôt que les symptômes.

✔ Améliorer le code lorsqu’une occasion raisonnable se présente.

✔ Respecter les standards établis.

---

Ce que nous évitons

✘ Développer sans comprendre le besoin.

✘ Ajouter de la complexité inutile.

✘ Reporter systématiquement le refactoring.

✘ Copier du code sans en comprendre le fonctionnement.

✘ Sacrifier la qualité pour gagner quelques heures.

---

Notre engagement

Chaque ligne de code que nous écrivons doit contribuer à rendre une solution plus simple, plus fiable et plus utile.

Nous développons aujourd’hui en pensant aux personnes qui feront évoluer cette solution demain.

---

En pratique

Avant de considérer une fonctionnalité terminée, nous nous posons les questions suivantes :

* Cette solution est-elle réellement la plus simple ?
* Le code sera-t-il facile à comprendre dans deux ans ?
* Les responsabilités sont-elles clairement séparées ?
* Les décisions importantes sont-elles documentées ?
* Serions-nous fiers qu’un autre développeur lise ce code ?

---

Citation

Le meilleur code n’est pas celui qui impressionne. C’est celui que tout le monde comprend.
