# CHK-018 — Validation d’entrée BaseMAD

## Objectif

Valider qu’une idée, décision, hypothèse, méthode ou spécification mérite d’entrer dans BaseMAD.

Cette checklist évite d’accumuler des documents inutiles, trop vagues ou non raccordés.

---

## 1. Utilité

| Point | Statut |
|---|---|
| L’élément sert un besoin réel. | `[OK / À corriger]` |
| L’usage futur est clair. | `[OK / À corriger]` |
| Le problème réduit est identifiable. | `[OK / À corriger]` |
| L’élément mérite d’être retrouvé plus tard. | `[OK / À corriger]` |

---

## 2. Classement

| Point | Statut |
|---|---|
| Le type d’élément est clair. | `[OK / À corriger]` |
| Le dossier cible est identifié. | `[OK / À corriger]` |
| Le format est approprié : guide, play, template, checklist, produit, research ou décision. | `[OK / À corriger]` |
| Le statut est défini. | `[OK / À corriger]` |

---

## 3. Clarté

| Point | Statut |
|---|---|
| L’objectif est formulé clairement. | `[OK / À corriger]` |
| Le périmètre est explicite. | `[OK / À corriger]` |
| Les limites sont nommées. | `[OK / À corriger]` |
| Le document peut être compris sans relire toute la conversation. | `[OK / À corriger]` |

---

## 4. Qualité documentaire

| Point | Statut |
|---|---|
| L’en-tête YAML est présent. | `[OK / À corriger]` |
| Le nom du fichier est clair. | `[OK / À corriger]` |
| Le document est sobre et professionnel. | `[OK / À corriger]` |
| Les termes sont cohérents avec le Système MAD. | `[OK / À corriger]` |

---

## 5. Raccordement

| Point | Statut |
|---|---|
| L’élément est ajouté au bon README. | `[OK / À corriger]` |
| L’élément est relié à une roadmap ou progression si nécessaire. | `[OK / À corriger]` |
| L’élément pointe vers une checklist si nécessaire. | `[OK / À corriger]` |
| L’élément pointe vers une source si un claim ou une hypothèse est présent. | `[OK / À corriger]` |

---

## 6. Risques

| Point | Statut |
|---|---|
| L’élément ne crée pas de promesse excessive. | `[OK / À corriger]` |
| L’élément ne duplique pas inutilement un document existant. | `[OK / À corriger]` |
| L’élément ne mélange pas hypothèse et décision. | `[OK / À corriger]` |
| L’élément ne contourne pas un standard existant. | `[OK / À corriger]` |

---

## Décision

```text
Décision : [Accepter dans BaseMAD / Corriger / Rejeter / Archiver]
Raison : [Résumé]
Raccordement requis : [README, checklist, roadmap, source]
Prochaine action : [Action]
```

---

## Critère d’acceptation

Un élément peut entrer dans BaseMAD si :

```text
son utilité est claire,
son format est approprié,
son périmètre est explicite,
il est raccordé,
et il ne crée pas de risque documentaire ou produit inutile.
```
