# PLAY-023 — Publier le site Web MAD DevOps

## Objectif

Publier ou mettre à jour le site Web MAD DevOps sans perdre la clarté du message, la simplicité du parcours ou la cohérence commerciale.

---

## Principe

```text
Clair avant beau.
Utile avant spectaculaire.
Contact facile avant effets visuels.
```

---

# 1. Lire les sources

Avant de modifier le site, lire :

```text
architecture-site-web-mad-devops.md
template-contenu-site-complet-mad-devops.md
presence-web-mad-devops.md
message-site-web-mad-devops.md
```

---

# 2. Valider la structure

Vérifier que le site contient :

- accueil;
- services;
- portfolio;
- à propos;
- FAQ;
- contact.

---

# 3. Valider les CTA

Les appels à l’action doivent rester simples :

```text
Parler de votre besoin
Voir les façons de commencer
```

---

# 4. Vérifier le formulaire

Le formulaire doit :

- être facile à comprendre;
- demander peu d’informations;
- permettre de décrire un besoin sans jargon;
- inclure le consentement à être recontacté.

---

# 5. Valider avant publication

Utiliser :

```text
chk-015-validation-site-web-mad-devops.md
```

---

## Critère de réussite

Le site est prêt si un visiteur peut comprendre rapidement ce que MAD DevOps fait et comment entrer en contact.
