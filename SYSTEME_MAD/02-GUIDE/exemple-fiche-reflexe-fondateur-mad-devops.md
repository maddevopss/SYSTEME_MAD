# Exemple — Fiche réflexe fondateur MAD DevOps

## Objectif

Montrer comment utiliser la fiche réflexe fondateur dans des situations concrètes, rapides et imparfaites.

Cet exemple sert à valider que la fiche fonctionne quand le fondateur est dans le jus, en reprise après interruption ou devant une situation floue.

---

## Rappel

```text
Si c’est flou, on clarifie.
Si ça bloque, on identifie la prochaine action.
Si ça revient souvent, on améliore le système.
```

---

# 1. Situation — Un client demande un prix trop tôt

## Message reçu

```text
Bonjour, j’aimerais savoir combien ça coûterait pour me faire un petit système de gestion simple.
```

## Réflexe

Ne pas donner un chiffre rapide sur un besoin flou.

## Document à ouvrir

```text
SYSTEME_MAD/02-GUIDE/offre-simple-mad-devops.md
SYSTEME_MAD/05-PLAY/play-014-decouverte-client-mad-devops.md
```

## Action

Répondre avec une clarification courte :

```text
Je pourrais vous donner un chiffre rapide, mais il risquerait d’être faux. Pour vous répondre correctement, il faut d’abord clarifier le besoin, les limites et ce qui serait réellement utile dans une première version.
```

## Résultat attendu

- le prix n’est pas improvisé;
- le besoin est ramené vers la découverte;
- aucune promesse ferme n’est faite trop tôt.

---

# 2. Situation — Un projet bloque

## Constat

```text
Le livrable est presque prêt, mais il manque un accès client.
```

## Réflexe

Traiter l’accès manquant comme un risque projet, pas comme un détail technique.

## Document à ouvrir

```text
SYSTEME_MAD/07-TEMPLATES/template-fiche-projet-client-mad-devops.md
```

## Action

Mettre à jour la section :

```text
Accès requis avant démarrage
```

avec :

- accès manquant;
- responsable client;
- date cible;
- impact si absent;
- prochaine action.

## Résultat attendu

- le blocage devient visible;
- le client sait ce qui est attendu;
- la prochaine action est claire.

---

# 3. Situation — Une opportunité tombe sans suite

## Constat

```text
Le prospect ne répond plus après la proposition.
```

## Réflexe

Ne pas seulement classer comme échec. Capturer l’apprentissage.

## Document à ouvrir

```text
SYSTEME_MAD/07-TEMPLATES/template-fiche-apprentissage-opportunite-mad-devops.md
```

## Questions

```text
Qu’est-ce qui était clair ?
Qu’est-ce qui est resté flou ?
Est-ce que la prochaine action était assez simple ?
Est-ce que le besoin était vraiment qualifié ?
Qu’est-ce que je garde pour la prochaine fois ?
```

## Résultat attendu

- l’opportunité est fermée proprement;
- un apprentissage est conservé;
- le système peut être amélioré sans blâme.

---

# 4. Situation — Trop de documents ouverts

## Constat

```text
Je suis en train d’ouvrir trop de guides, templates et checklists pour une seule décision.
```

## Réflexe

Revenir au minimum vital.

## Document à ouvrir

```text
SYSTEME_MAD/02-GUIDE/fiche-reflexe-fondateur-mad-devops.md
```

## Action

Faire seulement :

```text
1. Identifier une prochaine action.
2. Faire une relance importante.
3. Noter un apprentissage ou une célébration.
```

## Résultat attendu

- la surcharge diminue;
- une action avance;
- le fil est conservé.

---

# 5. Situation — Une friction revient souvent

## Constat

```text
La même confusion revient dans plusieurs projets.
```

## Réflexe

Transformer la friction en amélioration système.

## Document à ouvrir

```text
SYSTEME_MAD/07-TEMPLATES/template-registre-ameliorations-systeme-mad-devops.md
```

## Action

Ajouter une entrée :

```text
Source : projet / journal / livraison / opportunité
Problème : friction observée
Amélioration proposée : changement simple
Priorité : P1 / P2 / P3
Prochaine action : une seule action claire
```

## Résultat attendu

- la friction n’est pas oubliée;
- elle est priorisée;
- elle peut devenir un changement réel.

---

## Verdict de l’exemple

La fiche réflexe fonctionne si elle permet de passer rapidement de :

```text
Je suis bloqué / dans le flou.
```

à :

```text
Je sais quoi ouvrir.
Je sais quoi faire maintenant.
Je sais quoi noter pour améliorer le système.
```
