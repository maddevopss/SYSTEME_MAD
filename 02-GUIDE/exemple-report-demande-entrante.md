# Exemple — Report demande entrante

## Objectif

Montrer comment reporter une demande intéressante, mais pas assez claire ou mûre pour devenir une opportunité maintenant.

## Demande reçue

```text
J’aimerais éventuellement améliorer mon site et automatiser certaines tâches, mais je ne suis pas encore prêt. Je veux surtout savoir si c’est le genre de chose que vous faites.
```

---

## Qualification rapide

| Axe | Évaluation |
|---|---|
| Clarté de la demande | Floue mais intéressante |
| Alignement avec MAD DevOps | Moyen à fort |
| Type de besoin | Site Web / automatisation |
| Risque de mauvais cadrage | Moyen |
| Niveau d’urgence | Faible |
| Prochaine action | Réponse simple + suivi futur possible |
| Statut | Reportée |

---

## Décision

```text
Ne pas créer d’opportunité maintenant.
Ne pas proposer une offre terrain.
Répondre simplement.
Garder le contexte au registre si pertinent.
```

---

## Réponse proposée

```text
Bonjour [Nom],

Merci pour votre message.

Oui, ce sont des sujets sur lesquels MAD DevOps peut généralement aider : clarifier un site Web, améliorer un parcours ou réduire certaines tâches répétitives.

Comme le besoin n’est pas encore prêt, je vous proposerais de le reprendre lorsque vous aurez un exemple concret de ce qui vous ralentit ou de ce que vous aimeriez améliorer en premier.

Merci,
Marc-André Dufour
MAD DevOps
```

---

## Validation CHK-028

```text
Raison de report claire : oui
Aucune promesse inutile : oui
Aucun prix inventé : oui
Statut final clair : oui
```
