# CHK-028 — Validation fermeture demande entrante

## Objectif

Valider qu’une demande entrante peut être fermée, refusée poliment, reportée ou archivée sans brûler de pont et sans créer de malaise inutile.

Cette checklist protège la relation, le temps du fondateur et la clarté commerciale de MAD DevOps.

## Principe

```text
Fermer proprement vaut mieux que traîner une fausse opportunité.
```

---

## Quand fermer une demande

Une demande peut être fermée si :

- elle n’est pas alignée avec MAD DevOps;
- elle reste trop floue après clarification raisonnable;
- elle exige une promesse ou un prix trop tôt;
- elle sort du périmètre actuel;
- elle n’a pas de prochaine action utile;
- elle devrait plutôt être reportée ou archivée.

---

## Checklist

### 1. Qualification minimale

- [ ] La demande a été lue attentivement.
- [ ] Le besoin apparent a été résumé.
- [ ] L’alignement avec MAD DevOps a été évalué.
- [ ] Le risque de mauvais cadrage a été évalué.

---

### 2. Décision de fermeture

- [ ] La raison de fermeture est claire.
- [ ] La fermeture n’est pas une réaction impulsive.
- [ ] La demande ne mérite pas une offre terrain immédiate.
- [ ] Aucune prochaine action commerciale utile n’est perdue.

---

### 3. Réponse humaine

- [ ] Le message remercie la personne.
- [ ] Le refus ou report est formulé simplement.
- [ ] Le ton reste professionnel et respectueux.
- [ ] Le message ne se justifie pas excessivement.

---

### 4. Protection commerciale

- [ ] Aucun prix n’est inventé.
- [ ] Aucune promesse n’est faite pour éviter le malaise.
- [ ] Aucun détail de la mécanique interne n’est exposé.
- [ ] La porte reste ouverte seulement si c’est pertinent.

---

### 5. Statut final

- [ ] La demande est classée : fermée, reportée, non alignée ou archivée.
- [ ] Le pipeline est mis à jour si une entrée existait.
- [ ] Un suivi futur est noté seulement si utile.
- [ ] L’apprentissage est noté si la demande révèle un signal intéressant.

---

## Résultat de validation

- [ ] Fermer poliment
- [ ] Reporter
- [ ] Archiver
- [ ] Répondre avec une dernière question
- [ ] Réévaluer comme opportunité

---

## Critères d’acceptation

La fermeture est acceptée si :

1. la raison est claire;
2. le message reste humain;
3. aucune promesse inutile n’est faite;
4. la relation n’est pas abîmée;
5. le système reste propre.
