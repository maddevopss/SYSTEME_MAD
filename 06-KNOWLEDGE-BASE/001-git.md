ACADEMY-001 — Git

Objectif

Comprendre Git comme un outil de mémoire, de sécurité et de collaboration.

---

Pourquoi apprendre Git

Git permet de suivre l’évolution d’un projet.

Il garde l’historique des changements, permet de revenir en arrière et facilite le travail structuré.

Chez MAD DevOps, Git n’est pas seulement un outil technique.

C’est une façon de protéger le travail accompli.

---

Ce que Git permet

Git permet de :

* conserver l’historique du projet;
* comprendre ce qui a changé;
* revenir à une version précédente;
* travailler sur plusieurs branches;
* collaborer plus facilement;
* documenter l’évolution d’un projet.

---

Les concepts essentiels

Repository

Un dépôt Git contient le projet et son historique.

Commit

Un commit représente un point de sauvegarde clair dans l’évolution du projet.

Branch

Une branche permet de travailler sur une modification sans affecter directement la version principale.

Merge

Un merge permet d’intégrer les changements d’une branche dans une autre.

Remote

Un remote est une copie distante du projet, souvent hébergée sur GitHub.

---

Commandes de base

Initialiser un projet

git init

Voir l’état du projet

git status

Ajouter des fichiers

git add .

Créer un commit

git commit -m "message clair"

Lier un dépôt GitHub

git remote add origin https://github.com/UTILISATEUR/NOM_DU_REPO.git

Envoyer vers GitHub

git push -u origin main

---

Bonnes pratiques

* Faire des commits fréquents.
* Écrire des messages clairs.
* Ne pas mélanger plusieurs sujets dans un même commit.
* Vérifier git status avant de committer.
* Ne jamais committer de secrets.
* Utiliser des branches pour les changements importants.

---

Exemple de bon message de commit

git commit -m "docs(handbook): ajout du chapitre Git Academy"

---

Exemple de mauvais message de commit

git commit -m "update"

Ce message ne permet pas de comprendre ce qui a changé.

---

Workflow simple MAD DevOps

git status
git add .
git commit -m "type(scope): description claire"
git push

---

Types de commit recommandés

* docs : documentation
* feat : nouvelle fonctionnalité
* fix : correction
* refactor : amélioration du code sans changer le comportement
* test : ajout ou modification de tests
* chore : tâche technique
* style : formatage ou présentation

---

Exemple complet

git checkout -b docs/academy-git
git add .
git commit -m "docs(academy): ajout du module Git"
git push -u origin docs/academy-git

---

À retenir

Git n’est pas seulement un outil pour développeurs.

C’est la mémoire technique d’un projet.

Bien utilisé, il protège le travail, facilite la collaboration et permet de comprendre l’évolution d’une solution.

---

Citation

Un projet sans historique est un projet qui oublie comment il s’est construit.
