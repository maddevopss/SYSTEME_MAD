# CHK-037 — Validation revue mensuelle Early Access MADSuite

## Objectif

Cette checklist valide qu’une revue mensuelle Early Access MADSuite est prête à être tenue ou finalisée.

Elle sert à vérifier que la revue produit des décisions utiles, des priorités réalistes et des documents à mettre à jour.

## 1. Préparation

- [ ] Le dashboard du mois est disponible.
- [ ] Le rapport mensuel est disponible.
- [ ] Les retours du mois sont regroupés.
- [ ] Le backlog post-feedback est prêt.
- [ ] Les décisions produit pertinentes ont été relues.
- [ ] La version produit analysée est indiquée.

---

## 2. Activation

- [ ] Les demandes Early Access sont connues.
- [ ] Les invitations envoyées sont connues.
- [ ] Les activations sont connues.
- [ ] L’étape la moins fluide est identifiée.
- [ ] Une action est proposée si nécessaire.

---

## 3. Première valeur

- [ ] La revue vérifie le chemin vers la première action utile.
- [ ] La revue vérifie le chemin vers la première facture.
- [ ] La revue vérifie les signaux liés au PDF ou aux montants dus lorsque pertinent.
- [ ] La revue identifie ce qui ralentit le plus la première valeur.
- [ ] Les priorités restent reliées au Revenue Core.

---

## 4. Feedback

- [ ] Les retours sont regroupés en tendances.
- [ ] Les signaux isolés sont gardés en contexte.
- [ ] Les retours sont classés simplement.
- [ ] Les retours sont liés à des parcours produit.
- [ ] Les retours mènent à des actions claires ou à un report justifié.

---

## 5. Backlog

- [ ] Les items P0/P1 sont visibles.
- [ ] Chaque item prioritaire répond à un problème utilisateur clair.
- [ ] Chaque item prioritaire est relié à un parcours essentiel ou à une justification explicite.
- [ ] Les items P2/P3 sont séparés.
- [ ] Les items reportés ont une raison courte.

---

## 6. Décisions

- [ ] Les décisions à confirmer sont listées.
- [ ] Les nouvelles décisions proposées sont listées.
- [ ] Les décisions à reporter sont listées.
- [ ] Le registre des décisions produit est identifié comme document cible si nécessaire.
- [ ] Aucune décision majeure ne reste implicite.

---

## 7. Priorités du mois suivant

- [ ] Les priorités sont limitées en nombre.
- [ ] Chaque priorité a une justification courte.
- [ ] Chaque priorité a un document ou parcours lié.
- [ ] Les priorités sont réalistes pour un mois.
- [ ] Les priorités ne contredisent pas le Revenue Core.

---

## 8. Garde-fous MADSuite

- [ ] La revue garde le focus sur le produit réel.
- [ ] La revue évite de complexifier le MVP sans justification.
- [ ] La revue évite les promesses publiques excessives.
- [ ] La revue évite les collectes inutiles.
- [ ] La revue conserve le positionnement non médical de MADSuite.

---

## 9. Documents à mettre à jour

- [ ] Backlog post-feedback.
- [ ] Registre des décisions produit.
- [ ] Roadmap si nécessaire.
- [ ] Rapport mensuel si nécessaire.
- [ ] Page publique ou FAQ si nécessaire.
- [ ] Templates Early Access si nécessaire.
- [ ] Registre des risques si nécessaire.

---

## 10. Verdict

- [ ] Revue prête.
- [ ] Revue prête avec corrections mineures.
- [ ] Revue à compléter.
- [ ] Revue non prête.

Notes :

```text

Documents à mettre à jour :
Prochaine action :
```

---

## Phrase de contrôle

> Est-ce que cette revue mensuelle clarifie réellement les priorités du prochain mois?
