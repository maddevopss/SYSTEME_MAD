# Architecture site Web MAD DevOps

## Objectif

Ce guide définit la structure recommandée du site Web MAD DevOps.

L’objectif est de transformer la présence Web documentée en un site simple, clair, crédible et orienté vers la prise de contact.

---

## Principe central

```text
Comprendre vite.
Faire confiance.
Savoir quoi faire ensuite.
```

---

## Structure recommandée

| Page / section | Rôle | Document source |
|---|---|---|
| Accueil | Expliquer rapidement ce que MAD DevOps fait et pour qui. | `template-page-accueil-mad-devops.md` |
| Services | Présenter les façons simples de commencer. | `offres-packagees-mad-devops.md` |
| À propos | Présenter le studio et l’approche. | `template-a-propos-mad-devops.md` |
| Portfolio | Montrer des réalisations ou preuves publiables. | `portfolio-mad-devops.md` |
| FAQ | Répondre aux objections fréquentes. | `template-faq-site-web-mad-devops.md` |
| Contact | Recevoir une demande entrante claire. | `template-formulaire-contact-mad-devops.md` |

---

## Navigation minimale

```text
Accueil
Services
Portfolio
À propos
FAQ
Contact
```

---

## Appels à l’action recommandés

```text
Parler de votre besoin
Voir les façons de commencer
```

---

## Règles de contenu

- éviter le jargon technique inutile;
- expliquer les problèmes réglés avant les technologies;
- ne pas promettre de résultat garanti;
- garder les textes courts;
- rendre le contact facile;
- présenter les preuves sans exposer d’informations sensibles.

---

## Critère de réussite

Le site est utile si un visiteur comprend rapidement :

```text
ce que MAD DevOps fait,
pour qui,
quel problème le studio peut aider à clarifier,
et quelle prochaine action poser.
```
