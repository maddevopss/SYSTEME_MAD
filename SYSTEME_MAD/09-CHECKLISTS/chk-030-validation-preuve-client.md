# CHK-030 — Validation preuve client

## Objectif

Valider qu’une preuve client peut être utilisée, partagée ou publiée sans exposer le client, sans exagérer les résultats et sans révéler la mécanique interne MAD DevOps.

Cette checklist s’applique aux témoignages, références privées, fiches projets publiques, études de cas, captures autorisées et apprentissages internes.

## Principe

```text
Une preuve client est valide si elle renforce la confiance sans trahir la confiance.
```

---

## 1. Permission et statut

- [ ] La preuve a un type clair : témoignage, référence, fiche projet, étude de cas, capture ou apprentissage interne.
- [ ] Le statut de permission est connu.
- [ ] Le registre des preuves client est à jour.
- [ ] Le client est nommé seulement si l’autorisation est explicite.
- [ ] Les captures sont utilisées seulement si elles sont autorisées.

---

## 2. Protection du client

- [ ] Aucune donnée sensible n’est publiée.
- [ ] Les éléments confidentiels sont retirés ou anonymisés.
- [ ] Le secteur, le nom ou le contexte ne permettent pas d’identifier le client sans permission.
- [ ] Les captures ne montrent pas d’information privée.
- [ ] La version publique respecte la frontière public / privé.

---

## 3. Véracité et prudence

- [ ] La preuve ne contient pas de résultat inventé.
- [ ] Les chiffres sont présents seulement s’ils sont mesurés ou validés.
- [ ] Le texte ne promet pas que le même résultat sera obtenu ailleurs.
- [ ] Les limites sont indiquées si nécessaire.
- [ ] La valeur livrée est décrite simplement et honnêtement.

---

## 4. Utilité commerciale

- [ ] La preuve montre un problème réel.
- [ ] La preuve explique ce qui a été clarifié, amélioré ou livré.
- [ ] La preuve peut aider un prospect à comprendre le type de problème traité.
- [ ] La technologie n’écrase pas le problème client.
- [ ] La preuve soutient une discussion commerciale sans survente.

---

## 5. Usage prévu

- [ ] L’usage est identifié : public, privé, portfolio, proposition, site Web ou apprentissage interne.
- [ ] La preuve est validée avec CHK-026 si elle devient publique.
- [ ] La prochaine action est claire : demander, anonymiser, publier, archiver ou garder privé.
- [ ] La preuve n’est pas laissée sans statut.

---

## Résultat de validation

- [ ] Prête pour usage public
- [ ] Prête pour usage privé seulement
- [ ] À anonymiser
- [ ] Permission à demander
- [ ] À corriger
- [ ] À archiver

---

## Critères d’acceptation

La preuve client est acceptée si :

1. la permission est claire;
2. le client est protégé;
3. le résultat n’est pas exagéré;
4. la valeur livrée est compréhensible;
5. l’usage prévu est défini;
6. le registre est à jour.
