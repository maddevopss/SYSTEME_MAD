# CHK-024 — Validation offre terrain MAD DevOps

## Objectif

Valider qu’une offre terrain est claire, utile, réaliste et prête à être envoyée.

Cette checklist évite d’envoyer un message trop flou, trop technique, trop long ou trop prometteur.

## Principe

```text
Une offre terrain doit être assez claire pour avancer, mais assez simple pour ne pas bloquer la conversation.
```

---

## Checklist

### 1. Besoin compris

- [ ] Le besoin est résumé en une phrase simple.
- [ ] Le résumé ne force pas une solution non demandée.
- [ ] Le contexte du contact est respecté.

---

### 2. Aide proposée

- [ ] L’aide proposée correspond au besoin.
- [ ] Le format est simple : diagnostic, mini-mandat, amélioration, automatisation ou cadrage.
- [ ] L’offre ne promet pas une capacité non validée.
- [ ] L’offre est compréhensible sans jargon.

---

### 3. Prochaine étape

- [ ] Une seule prochaine étape est proposée.
- [ ] La prochaine étape est concrète.
- [ ] Le contact peut répondre facilement.
- [ ] La prochaine étape ne met pas de pression artificielle.

---

### 4. Clarté du message

- [ ] Le message est court.
- [ ] Le ton est humain et professionnel.
- [ ] Le message peut être lu rapidement.
- [ ] Le message ne ressemble pas à une vente forcée.

---

### 5. Garde-fous

- [ ] Aucune promesse exagérée.
- [ ] Aucun jargon inutile.
- [ ] Aucun prix ou délai inventé.
- [ ] Aucune proposition complète envoyée trop tôt.
- [ ] Le pipeline est mis à jour après l’envoi.

---

## Résultat de validation

- [ ] Offre prête à envoyer
- [ ] Offre à simplifier
- [ ] Besoin à clarifier avant envoi
- [ ] Offre à remplacer par une question
- [ ] Opportunité à fermer ou archiver

---

## Critères d’acceptation

Une offre terrain est acceptée si :

1. le besoin est clair;
2. l’aide proposée est réaliste;
3. la prochaine étape est simple;
4. le message reste humain;
5. aucun engagement non validé n’est ajouté.
