# Lexique public / privé MAD DevOps

## Objectif

Définir les mots et formulations à utiliser publiquement, et ceux à garder internes.

Ce lexique aide à publier des contenus clairs pour les clients sans exposer les systèmes, méthodes et avantages stratégiques de MAD DevOps.

## Principe

```text
Le vocabulaire public doit expliquer le bénéfice sans nommer toute la mécanique.
```

---

## Tableau de traduction

| Terme interne | Usage public recommandé | Note |
|---|---|---|
| CerveauMAD | organisation interne de travail | Ne pas présenter comme méthode publique complète. |
| Machine à clients | parcours simple pour commencer | Garder la mécanique commerciale privée. |
| BaseMAD | base documentaire interne | Ne pas exposer comme architecture complète. |
| Playbook | façon de faire / démarche | Résumer sans publier les étapes internes. |
| Checklist interne | validation de clarté | Ne pas publier la liste complète. |
| Pipeline commercial | prochaine étape | Garder le suivi interne privé. |
| Mesures internes | apprentissages généraux | Ne pas publier les mesures brutes. |
| Prompts / agents | assistance interne | Ne pas exposer les prompts détaillés. |
| Décision stratégique | orientation interne | Garder privé. |
| Guide client rapide | guide pour choisir la bonne prochaine étape | Peut être public si simplifié. |

## Mots à éviter publiquement sans contexte

```text
CerveauMAD
Machine à clients
BaseMAD
système interne complet
playbook complet
checklist interne
pipeline interne
mécanique commerciale
prompt interne
agent interne
```

## Exemple de reformulation

### Interne

```text
Cette idée passe par la Machine à clients, la matrice public / privé et CHK-026.
```

### Public

```text
On commence par clarifier votre besoin, puis on choisit la prochaine étape la plus simple.
```

---

## Règle rapide

```text
Si le mot fait comprendre la valeur, il peut être public.
Si le mot révèle la mécanique, il reste interne.
```
