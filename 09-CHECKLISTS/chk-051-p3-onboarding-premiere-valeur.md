# CHK-051 — P3 Onboarding et première valeur

## Rôle du document

Cette checklist valide le premier parcours produit : arriver dans MADSuite, comprendre quoi faire, créer une première valeur utile.

---

## Objectif

Un nouvel utilisateur doit pouvoir :

1. comprendre l’utilité de MADSuite;
2. configurer son organisation;
3. créer un client;
4. créer un projet;
5. démarrer ou saisir du temps;
6. comprendre comment transformer ce temps en valeur facturable.

---

## Préconditions

- [ ] P2 fermée ou exception documentée.
- [ ] Environnement de test disponible.
- [ ] Compte test propre.
- [ ] Données de test non sensibles.

---

## Parcours onboarding

| Étape | Validation | Résultat |
|---|---|---|
| Création organisation | Nom, devise, taxes si applicable | À tester |
| Choix ou affichage des modules | Modules disponibles cohérents avec le plan | À tester |
| Premier CTA | Action claire après onboarding | À tester |
| Empty states | Messages utiles, pas techniques | À tester |
| Retour dashboard | Prochaine action évidente | À tester |

---

## Première valeur

| Étape | Validation | Résultat |
|---|---|---|
| Créer client | Client sauvegardé et visible | À tester |
| Créer projet | Projet lié au client | À tester |
| Démarrer timer | Timer démarre sans confusion | À tester |
| Ajouter note | Note attachée au temps si applicable | À tester |
| Arrêter timer | Entrée temps créée | À tester |
| Voir timesheet | Entrée compréhensible | À tester |
| Créer facture | Données reprises correctement | À tester |

---

## UX cognitive

| Point | Validation | Résultat |
|---|---|---|
| Trop de choix | L’interface ne surcharge pas le départ | À tester |
| Prochaine action | L’utilisateur sait quoi faire ensuite | À tester |
| Messages | Ton clair, non culpabilisant | À tester |
| Assistance | Aide utile, pas intrusive | À tester |

---

## Contraintes MADPROOF

- [ ] Aucun claim médical.
- [ ] Aucune promesse de correction du TDAH.
- [ ] Aucune suggestion de diagnostic.
- [ ] Les aides cognitives restent opérationnelles.
- [ ] Le contrôle utilisateur est clair.

---

## Critère de réussite

Le parcours est considéré valide si un utilisateur test peut créer une première entrée de temps utile et comprendre comment elle devient facturable sans aide externe majeure.
