# PLAY-019 — Transformer une livraison en preuve client

## Objectif

Transformer une livraison client réussie en preuve crédible pour MAD DevOps, sans pression commerciale et sans exposer d’information sensible.

---

## Principe

```text
Livrer d’abord.
Demander ensuite.
Publier seulement avec permission.
```

---

# 1. Vérifier que le projet est prêt

Avant de demander une preuve, vérifier :

- le livrable est accepté;
- les ajustements principaux sont terminés;
- le client comprend la valeur livrée;
- aucune tension majeure n’est ouverte;
- les informations sensibles sont identifiées.

---

# 2. Choisir le type de preuve

Selon le contexte, choisir :

- témoignage court;
- référence privée;
- fiche projet publique;
- étude de cas anonymisée;
- capture autorisée;
- simple apprentissage interne.

---

# 3. Demander sans pression

Utiliser le template approprié :

```text
template-demande-temoignage-client-mad-devops.md
template-demande-reference-client-mad-devops.md
template-autorisation-publication-projet-mad-devops.md
```

---

# 4. Valider avant publication

Avant de publier, confirmer :

- ce qui peut être nommé;
- ce qui doit rester anonyme;
- les captures autorisées;
- les informations à retirer;
- la formulation finale.

---

# 5. Produire la preuve

Créer ensuite :

```text
template-etude-de-cas-client-mad-devops.md
template-fiche-projet-public-mad-devops.md
```

---

## Critère de réussite

La preuve est valide si elle renforce la confiance sans exposer le client.
