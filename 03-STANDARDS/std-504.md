# STD-504 — Agents IA

## Règle d’or

Un agent IA doit agir dans un cadre clair, traçable et limité.

---

## Objectif

Définir les règles d’usage des agents IA dans les workflows MAD DevOps.

Un agent IA peut accélérer l’analyse, la rédaction, la revue ou l’exécution de tâches, mais il ne doit pas créer de changements incontrôlés.

---

## Règles obligatoires

- Définir la mission de l’agent avant son utilisation.
- Définir les fichiers, dossiers ou systèmes qu’il peut modifier.
- Exiger une sortie lisible et vérifiable.
- Ne pas permettre à un agent de supprimer ou remplacer une source officielle sans validation.
- Demander à l’agent de signaler les incertitudes, doublons et risques.
- Relire les changements importants avant de les considérer terminés.

---

## Bonnes pratiques

✔ Donner à l’agent les documents de référence avant la tâche.

✔ Limiter le périmètre d’action.

✔ Utiliser des checklists de validation.

✔ Demander un résumé des changements effectués.

✔ Conserver une trace des décisions importantes.

✔ Éviter les agents trop autonomes sur les données sensibles.

---

## Anti-patterns

### Mauvais

Demander à un agent de “tout améliorer” sans périmètre.

### Mauvais

Laisser un agent créer plusieurs versions concurrentes d’un document.

### Mauvais

Accepter les changements d’un agent sans validation humaine.

---

## Cas réel Système MAD

Un agent IA qui modifie le Système MAD doit lire :

- `README.md`;
- `SYSTEME_MAD/MANIFEST.md`;
- `SYSTEME_MAD/00-SYSTEME-MAD/ai-context.md`;
- les standards applicables;
- les ADR applicables.
