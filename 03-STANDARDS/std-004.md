STD-004 — Journalisation

Règle d’or

Les journaux servent à comprendre les événements, jamais à deviner ce qui s’est produit.

---

Objectif

Définir les règles de journalisation utilisées dans les projets MAD DevOps afin d’assurer un suivi fiable des événements, de faciliter le diagnostic des incidents et d’améliorer la qualité du support.

Une bonne journalisation doit fournir suffisamment d’information pour comprendre une situation, sans compromettre la sécurité ou la confidentialité.

---

Pourquoi ce standard existe

Les journaux sont souvent la première source d’information lors d’un incident.

Une journalisation cohérente permet de :

* comprendre rapidement un problème;
* accélérer le diagnostic;
* faciliter le support technique;
* assurer la traçabilité des événements;
* améliorer continuellement les solutions.

---

Niveau de maturité

🟢 Fondamental

Ce standard s’applique à tous les projets développés par MAD DevOps.

---

Champ d’application

Ce standard s’applique à :

* toutes les API;
* toutes les applications Web;
* toutes les applications mobiles;
* toutes les applications desktop;
* tous les services d’arrière-plan;
* tous les scripts d’automatisation.

---

Règles obligatoires

Les journaux doivent être utiles

Chaque entrée doit apporter une information pertinente.

Journaliser pour accumuler des données inutiles est interdit.

---

Utiliser des niveaux de journalisation

Les niveaux suivants doivent être utilisés de façon cohérente :

* DEBUG
* INFO
* WARN
* ERROR
* FATAL

Chaque niveau possède une intention précise.

---

Les informations sensibles sont interdites

Les journaux ne doivent jamais contenir :

* mots de passe;
* jetons d’accès;
* clés API;
* numéros de carte bancaire;
* données personnelles inutiles;
* secrets d’application.

---

Structurer les journaux

Les journaux doivent être structurés afin de faciliter leur recherche et leur analyse.

Lorsque possible, privilégier un format structuré (JSON).

---

Contextualiser les événements

Chaque journal important devrait inclure, lorsque pertinent :

* utilisateur;
* organisation;
* identifiant de requête;
* module;
* action;
* date et heure.

---

Bonnes pratiques

✔ Journaliser les erreurs importantes.

✔ Journaliser les événements métier significatifs.

✔ Utiliser un format uniforme.

✔ Inclure le contexte nécessaire.

✔ Centraliser les journaux.

✔ Configurer une rotation des journaux.

✔ Conserver uniquement la durée nécessaire.

---

Anti-patterns

Mauvais

console.log(user);

Impossible de contrôler les informations affichées.

Risque de fuite de données.

---

Mauvais

logger.error(error);

Sans contexte, ce message est difficile à exploiter.

---

Bon

logger.error("Création de facture impossible", {
    organisationId,
    invoiceId,
    userId,
    error: error.message
});

Le journal contient les informations nécessaires sans exposer de données sensibles.

---

Exemples

Journal d’information

INFO
Utilisateur connecté.

---

Journal d’avertissement

WARN
Tentative d'accès refusée.

---

Journal d’erreur

ERROR
Connexion à la base de données impossible.

Chaque niveau correspond à une gravité différente et facilite la surveillance des systèmes.

---

Cas réel MAD DevOps

MADSuite

MADSuite utilise une journalisation structurée afin de suivre :

* les connexions;
* les erreurs applicatives;
* les traitements automatisés;
* les événements critiques;
* les opérations d’administration.

Les journaux permettent d’identifier rapidement les incidents tout en protégeant les renseignements confidentiels des utilisateurs.

---

Exceptions

En environnement de développement, des informations supplémentaires peuvent être journalisées afin de faciliter le débogage.

Ces informations ne doivent jamais être conservées en production.
