# CHK-009 — Validation du bloc offre commerciale MAD DevOps

## Objectif

Valider que le bloc **Offre commerciale MAD DevOps** est clair, simple, cohérent et utilisable dans une vraie discussion client.

Cette checklist sert à éviter trois pièges : vendre trop vite, parler trop technique, ou promettre trop large.

---

## Principe

```text
Clair avant vendeur.
Simple avant complet.
Utile avant impressionnant.
```

# 1. Clarté de l’offre

- [ ] L’offre peut être expliquée sans jargon technique.
- [ ] Le client comprend le problème que MAD DevOps aide à régler.
- [ ] L’offre ne repose pas sur des mots comme DevOps, cloud ou architecture si le client n’en a pas besoin.
- [ ] L’offre reste orientée vers le résultat utile.
- [ ] La phrase centrale de MAD DevOps reste cohérente avec l’offre.

---

# 2. Portes d’entrée commerciales

- [ ] Les packages ou portes d’entrée sont faciles à comprendre.
- [ ] Chaque porte d’entrée correspond à un besoin client réel.
- [ ] Les offres ne se chevauchent pas inutilement.
- [ ] Le client peut savoir par où commencer.
- [ ] Le système permet de commencer petit sans perdre la suite.

---

# 3. Prix et promesses

- [ ] Le système évite de donner un prix sérieux sur un besoin flou.
- [ ] Une réponse existe quand le client demande un prix trop tôt.
- [ ] La proposition arrive après une clarification suffisante.
- [ ] Les limites et exclusions sont visibles.
- [ ] Les promesses restent réalistes.

---

# 4. Proposition client

- [ ] La proposition contient le contexte.
- [ ] La proposition contient le besoin identifié.
- [ ] La proposition contient les livrables.
- [ ] La proposition contient le hors périmètre.
- [ ] La proposition contient les responsabilités.
- [ ] La proposition contient la prochaine action.

---

# 5. Communication commerciale

- [ ] Les messages restent simples et humains.
- [ ] Les relances ne mettent pas de pression inutile.
- [ ] Un refus ou un report peut être formulé professionnellement.
- [ ] Le client sait toujours ce qui se passe ensuite.
- [ ] La communication protège la relation autant que la vente.

---

# 6. Cohérence avec le parcours client

- [ ] L’offre mène naturellement vers la découverte.
- [ ] La découverte mène vers la qualification.
- [ ] La qualification mène vers cadrage, proposition, Phase 0, report ou refus.
- [ ] Une proposition acceptée mène vers un démarrage clair.
- [ ] Une opportunité perdue peut produire un apprentissage.

---

# 8. Verdict

## Bloc validé

- [ ] L’offre est claire.
- [ ] L’offre est vendable sans jargon.
- [ ] L’offre protège contre les promesses trop rapides.
- [ ] L’offre mène naturellement vers le parcours client.
- [ ] L’offre peut être utilisée par un fondateur solo.

## À ajuster

- [ ] L’offre est trop vague.
- [ ] L’offre est trop technique.
- [ ] Un package est ambigu.
- [ ] Une promesse est trop large.
- [ ] Une réponse commerciale manque.

---

## Critère de réussite

Le bloc **Offre commerciale MAD DevOps** est validé s’il permet de répondre rapidement :

```text
Qu’est-ce que MAD DevOps aide à régler ?
Par où le client peut-il commencer ?
Qu’est-ce qui est inclus ?
Qu’est-ce qui est hors périmètre ?
Pourquoi ne pas chiffrer trop tôt ?
Quelle est la prochaine action ?
```
