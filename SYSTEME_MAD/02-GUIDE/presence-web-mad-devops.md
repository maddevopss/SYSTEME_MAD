# Présence Web MAD DevOps

## Objectif

Ce guide définit le rôle de la présence Web de MAD DevOps.

Le site doit expliquer clairement ce que MAD DevOps fait, pour qui, et comment commencer une conversation sans jargon technique inutile.

---

## Principe central

```text
Comprendre vite.
Faire confiance.
Savoir quoi faire ensuite.
```

---

## Rôle du site

Le site Web doit servir à :

- présenter MAD DevOps simplement;
- expliquer les problèmes que le studio aide à régler;
- montrer les façons de commencer;
- rassurer les visiteurs non techniques;
- inviter à parler d’un besoin;
- soutenir la crédibilité du studio.

---

## Ce que le site n’est pas

Le site n’est pas :

- une vitrine de technologies;
- un portfolio surchargé;
- une promesse de tout automatiser;
- une page d’agence impersonnelle;
- un tunnel de vente agressif.

---

## Structure recommandée

1. Accueil.
2. Services ou façons de commencer.
3. À propos.
4. FAQ.
5. Contact.

---

## Message principal

```text
Des logiciels simples, fiables et adaptés à votre réalité.
```

---

## Appels à l’action

CTA principal :

```text
Parler de votre besoin
```

CTA secondaire :

```text
Voir les façons de commencer
```

---

## Critère de réussite

La présence Web est utile si un visiteur comprend rapidement :

```text
ce que MAD DevOps fait,
à qui cela s’adresse,
quel problème cela aide à régler,
et quelle prochaine action poser.
```
