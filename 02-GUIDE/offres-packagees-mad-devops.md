# Offres packagées MAD DevOps

## Objectif

Ce document définit des portes d’entrée simples pour guider un client vers une réponse claire.

L’objectif n’est pas d’enfermer tous les projets dans des forfaits rigides, mais de faciliter la discussion, réduire le flou et orienter le client vers la bonne prochaine étape.

---

## Principe

Un client ne sait pas toujours s’il a besoin d’un site Web, d’une application, d’une automatisation ou seulement d’un cadrage.

Les offres packagées servent à répondre :

```text
Voici les options simples pour commencer.
On choisit celle qui correspond le mieux à votre niveau de clarté et à votre besoin réel.
```

---

## Règle MAD DevOps

Ne pas vendre une réalisation complète si le besoin est flou.

Si le problème, le succès ou le périmètre ne sont pas clairs, orienter vers :

```text
Découverte
Cadrage
Phase 0
```

---

# Catégorie 1 — Découverte et cadrage

## Offre 1.1 — Appel découverte

### Pour qui

Client qui a une idée, un problème ou une demande, mais qui ne sait pas encore quoi faire.

### Objectif

Comprendre rapidement le contexte et déterminer la bonne prochaine étape.

### Inclus

- discussion structurée;
- clarification du problème principal;
- identification du niveau de clarté;
- recommandation de prochaine action.

### Sortie

```text
Prochaine action recommandée : proposition, cadrage, Phase 0 ou refus/retrait.
```

---

## Offre 1.2 — Cadrage express

### Pour qui

Client avec un besoin réel, mais un périmètre encore incomplet.

### Objectif

Transformer une demande floue en base de proposition claire.

### Inclus

- synthèse du besoin;
- utilisateurs concernés;
- première version utile;
- hors périmètre;
- risques principaux;
- questions ouvertes.

### Sortie

```text
Document de cadrage court + recommandation.
```

---

## Offre 1.3 — Phase 0 diagnostic

### Pour qui

Projet important, risqué ou trop flou pour être estimé correctement.

### Objectif

Clarifier le problème, le périmètre, les options et les risques avant engagement.

### Inclus

- analyse du besoin;
- cartographie simple du processus actuel;
- options de solution;
- risques;
- feuille de route préliminaire;
- décision de poursuite.

### Sortie

```text
Diagnostic + options + recommandation de suite.
```

# Catégorie 2 — Présence Web

## Offre 2.1 — Page vitrine simple

### Pour qui

Travailleur autonome ou petite entreprise qui veut une présence Web claire.

### Objectif

Présenter rapidement l’activité, les services et les moyens de contact.

### Inclus

- page d’accueil;
- section services;
- section à propos;
- appel à l’action;
- adaptation mobile;
- mise en ligne selon contexte.

### Sortie

```text
Site vitrine simple prêt à être partagé.
```

---

## Offre 2.2 — Site professionnel

### Pour qui

Client qui a besoin d’un site plus complet pour présenter son activité.

### Objectif

Créer un site clair, structuré et plus crédible.

### Inclus

- plusieurs sections ou pages;
- structure de contenu;
- responsive mobile;
- formulaire ou appel à l’action;
- base SEO simple;
- documentation minimale.

### Sortie

```text
Site Web professionnel prêt pour usage client.
```

---

## Offre 2.3 — Refonte légère

### Pour qui

Client qui possède déjà un site, mais qui le trouve dépassé, confus ou inefficace.

### Objectif

Améliorer la clarté, la structure et l’expérience utilisateur.

### Inclus

- analyse rapide de l’existant;
- recommandations;
- refonte visuelle ou structurelle légère;
- amélioration mobile;
- clarification des appels à l’action.

### Sortie

```text
Site existant amélioré et plus clair.
```

---

# Catégorie 3 — Automatisation et outils internes

## Offre 3.1 — Automatisation simple

### Pour qui

Client qui répète souvent une tâche manuelle.

### Objectif

Réduire les copier-coller, suivis manuels ou manipulations répétitives.

### Inclus

- identification du processus;
- automatisation d’une tâche précise;
- test du flux;
- documentation courte.

### Sortie

```text
Une tâche répétitive automatisée.
```

---

## Offre 3.2 — Tableau de bord simple

### Pour qui

Client qui veut voir ses informations importantes au même endroit.

### Objectif

Centraliser des données utiles dans une interface claire.

### Inclus

- identification des données;
- vue synthèse;
- indicateurs simples;
- interface Web légère;
- documentation d’utilisation.

### Sortie

```text
Tableau de bord simple et utilisable.
```

---

## Offre 3.3 — Mini-outil interne

### Pour qui

Client qui gère un processus dans Excel, courriels ou documents dispersés.

### Objectif

Créer un petit outil adapté à un besoin précis.

### Inclus

- écran ou module principal;
- gestion simple des données;
- actions essentielles;
- base de données si nécessaire;
- documentation minimale.

### Sortie

```text
Outil interne ciblé pour remplacer un processus manuel.
```

---

# Catégorie 4 — Applications et MVP

## Offre 4.1 — Prototype cliquable

### Pour qui

Client avec une idée d’application qui doit être clarifiée ou présentée.

### Objectif

Visualiser l’idée avant de construire le produit complet.

### Inclus

- écrans principaux;
- parcours utilisateur simple;
- structure fonctionnelle;
- points à valider;
- recommandation de suite.

### Sortie

```text
Prototype ou maquette utilisable pour valider l’idée.
```

---

## Offre 4.2 — MVP fonctionnel

### Pour qui

Client qui veut une première version utilisable d’un produit ou outil.

### Objectif

Construire la plus petite version utile qui règle le problème principal.

### Inclus

- fonctionnalités essentielles;
- structure frontend/backend selon besoin;
- base de données si nécessaire;
- déploiement selon contexte;
- documentation de base.

### Sortie

```text
Première version fonctionnelle et utilisable.
```

---

## Offre 4.3 — Module évolutif

### Pour qui

Client qui a déjà un système, mais veut ajouter une fonction précise.

### Objectif

Ajouter une capacité ciblée sans refaire tout le système.

### Inclus

- analyse du contexte existant;
- conception du module;
- intégration au système;
- tests essentiels;
- documentation.

### Sortie

```text
Module fonctionnel intégré ou prêt à intégrer.
```

---

# Catégorie 5 — Audit et amélioration

## Offre 5.1 — Audit express

### Pour qui

Client qui veut savoir ce qui bloque ou quoi améliorer.

### Objectif

Identifier rapidement les problèmes principaux et les prochaines actions.

### Inclus

- revue de l’existant;
- points forts;
- problèmes visibles;
- recommandations prioritaires.

### Sortie

```text
Synthèse d’audit + priorités.
```

---

## Offre 5.2 — Plan d’amélioration

### Pour qui

Client avec un site, outil ou processus existant qui doit être amélioré.

### Objectif

Créer un plan clair avant de corriger ou développer.

### Inclus

- analyse plus structurée;
- priorisation;
- risques;
- effort estimé;
- feuille de route.

### Sortie

```text
Plan d’amélioration utilisable pour décider de la suite.
```

---

## Offre 5.3 — Correction ciblée

### Pour qui

Client qui a un problème précis à corriger.

### Objectif

Corriger un irritant clair sans lancer un gros projet.

### Inclus

- compréhension du problème;
- correction ciblée;
- validation;
- note de livraison.

### Sortie

```text
Problème précis corrigé ou recommandation si correction impossible dans le cadre prévu.
```

# Comment orienter le client

## Si le client dit : « Je ne sais pas par où commencer »

Orienter vers :

```text
Appel découverte
Cadrage express
Phase 0 diagnostic
```

## Si le client dit : « J’ai besoin d’un site »

Orienter vers :

```text
Page vitrine simple
Site professionnel
Refonte légère
```

## Si le client dit : « Je fais trop de choses à la main »

Orienter vers :

```text
Automatisation simple
Tableau de bord simple
Mini-outil interne
```

## Si le client dit : « J’ai une idée d’application »

Orienter vers :

```text
Prototype cliquable
MVP fonctionnel
Module évolutif
```

## Si le client dit : « Mon système marche mal »

Orienter vers :

```text
Audit express
Plan d’amélioration
Correction ciblée
```

---

## Phrase d’orientation simple

```text
À ce stade, je vois trois façons simples de commencer. Si le besoin est encore flou, on commence par un cadrage. Si le besoin est clair, on peut préparer une proposition. Si le projet est plus risqué, je recommande une Phase 0 pour éviter de partir dans la mauvaise direction.
```

---

## Règle finale

Les offres packagées servent à guider la conversation.

Elles ne remplacent pas le jugement professionnel, le cadrage et la validation du besoin réel.
