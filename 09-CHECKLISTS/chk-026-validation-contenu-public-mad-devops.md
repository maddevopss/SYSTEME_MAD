# CHK-026 — Validation contenu public MAD DevOps

## Objectif

Valider qu’un contenu public MAD DevOps aide le client sans exposer la méthode interne, les systèmes stratégiques ou les détails confidentiels.

Cette checklist doit être utilisée avant de publier une page Web, une offre, un guide client, une publication ou un texte commercial.

## Principe

```text
Publier la clarté, garder la mécanique.
```

---

## Checklist

### 1. Utilité client

- [ ] Le contenu parle d’abord du besoin du client.
- [ ] Le contenu aide à comprendre une situation ou une prochaine étape.
- [ ] Le contenu n’est pas centré sur l’architecture interne MAD DevOps.
- [ ] Le langage est clair pour une personne non technique.

---

### 2. Protection de la méthode

- [ ] Le contenu ne révèle pas les routines internes complètes.
- [ ] Le contenu ne publie pas les playbooks internes.
- [ ] Le contenu ne publie pas les checklists internes complètes.
- [ ] Le contenu ne révèle pas les mesures internes brutes.
- [ ] Le contenu ne dévoile pas les décisions stratégiques.

---

### 3. Noms et concepts internes

- [ ] Les noms internes ne sont pas utilisés inutilement.
- [ ] CerveauMAD n’est pas présenté comme une méthode publique complète.
- [ ] Machine à clients n’est pas exposée comme mécanique détaillée.
- [ ] BaseMAD reste une structure interne sauf décision contraire.

---

### 4. Communication commerciale

- [ ] Le contenu reste simple et humain.
- [ ] Aucune promesse exagérée n’est ajoutée.
- [ ] Aucun jargon technique inutile n’est présent.
- [ ] La prochaine étape est claire.
- [ ] Le contenu ne donne pas toute la recette gratuitement.

---

### 5. Publication

- [ ] Le contenu est prêt pour le public visé.
- [ ] Le contenu peut être compris sans contexte interne.
- [ ] Les liens ou appels à l’action sont cohérents.
- [ ] Le contenu peut être retiré ou corrigé facilement si nécessaire.

---

## Résultat de validation

- [ ] Prêt à publier
- [ ] À simplifier
- [ ] À anonymiser
- [ ] À garder interne
- [ ] À retravailler

---

## Critères d’acceptation

Un contenu public est accepté si :

1. il aide le client;
2. il reste clair;
3. il évite le jargon;
4. il protège la méthode interne;
5. il ne publie pas l’avantage stratégique complet.
