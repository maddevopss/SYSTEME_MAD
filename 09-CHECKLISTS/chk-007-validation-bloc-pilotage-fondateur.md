# CHK-007 — Validation du bloc pilotage fondateur

## Objectif

Valider que le bloc **Pilotage fondateur** est complet, utilisable et suffisamment simple pour servir en contexte réel.

Cette checklist ferme le bloc sans ajouter une nouvelle couche de complexité.

---

## Principe

```text
Simple en façade.
Solide en profondeur.
Utile dans le jus.
```

Le bloc est réussi s’il aide à agir plus vite, à réduire le flou et à conserver les apprentissages sans créer une deuxième job administrative.

# 1. Utilisation rapide

- [ ] La fiche réflexe permet de décider quoi faire sans réfléchir longtemps.
- [ ] L’exemple de fiche réflexe montre comment l’utiliser dans des situations concrètes.
- [ ] La routine courte tient en 20 minutes le lundi.
- [ ] La routine courte tient en 10 à 15 minutes le vendredi.
- [ ] Le mode minimum vital existe pour les semaines chargées.
- [ ] Le cockpit indique quel document ouvrir selon la situation.

---

# 2. Couverture des situations réelles

Le bloc couvre :

- [ ] début de semaine;
- [ ] fin de semaine;
- [ ] nouveau prospect;
- [ ] besoin flou;
- [ ] demande de prix trop tôt;
- [ ] proposition à préparer;
- [ ] mandat qui démarre;
- [ ] projet qui bloque;
- [ ] accès client manquant;
- [ ] livraison à sécuriser;
- [ ] opportunité sans suite;
- [ ] friction récurrente;
- [ ] système qui devient trop lourd.

---

# 3. Garde-fous de simplicité

- [ ] Aucun document du bloc ne force à tout ouvrir.
- [ ] Les documents courts orientent vers les documents longs seulement si nécessaire.
- [ ] La routine courte limite le nombre de documents ouverts.
- [ ] Le registre des améliorations évite l’accumulation d’idées non traitées.
- [ ] La règle « une amélioration système par semaine » est visible.
- [ ] Le système peut être utilisé même quand l’énergie est basse.

---

# 4. Boucle d’amélioration continue

- [ ] Un problème peut être capturé dans le journal.
- [ ] Une friction peut être transformée en amélioration proposée.
- [ ] Une amélioration peut être priorisée dans le registre.
- [ ] Une amélioration peut modifier un template, guide, checklist, playbook ou une règle.
- [ ] Un exemple terrain a déjà produit une amélioration réelle.

---

- [ ] L’exemple de fiche réflexe est listé dans `SYSTEME_MAD/02-GUIDE/README.md`.
- [ ] La routine courte est listée dans `SYSTEME_MAD/02-GUIDE/README.md`.
- [ ] Le cockpit fondateur est listé dans `SYSTEME_MAD/02-GUIDE/README.md`.

---

# 6. Verdict

## Bloc validé

- [ ] Le bloc est complet.
- [ ] Le bloc est utilisable rapidement.
- [ ] Le bloc reste simple en façade.
- [ ] Le bloc permet de conserver les apprentissages.
- [ ] Le bloc peut être utilisé en solo sans surcharge.

## À ajuster

- [ ] Un document est trop long.
- [ ] Un document est mal indexé.
- [ ] Une situation réelle n’est pas couverte.
- [ ] La routine demande trop d’effort.
- [ ] Le système ajoute du flou au lieu d’en enlever.

---

## Critère de réussite

Le bloc **Pilotage fondateur** est validé s’il permet de répondre rapidement :

```text
Quoi faire maintenant ?
Quel document ouvrir ?
Qui relancer ?
Qu’est-ce qui bloque ?
Qu’est-ce que j’ai appris ?
Qu’est-ce que je simplifie ?
```
