# Template — Réponse à une demande entrante MAD DevOps

## Objectif

Répondre clairement à une demande reçue, sans promettre trop tôt, sans chiffrer avant clarification et sans exposer la mécanique interne.

Ce template s’utilise après la fiche de qualification de demande entrante.

## Réponse — demande claire

```text
Bonjour [Nom],

Merci pour votre message.

Voici ce que je comprends : [résumé bref du besoin].

Avant de proposer une solution ou une estimation, je préfère confirmer quelques éléments pour bien cadrer la suite.

La prochaine étape la plus simple serait [appel court / question / mini-cadrage].

Merci,
Marc-André Dufour
MAD DevOps
```

## Réponse — besoin flou mais pertinent

```text
Bonjour [Nom],

Merci pour votre message.

Votre demande semble pertinente, mais il manque encore quelques éléments pour bien comprendre le besoin.

Pour avancer proprement, j’aimerais clarifier :

1. le problème principal;
2. ce qui vous ralentit le plus;
3. ce qui serait utile comme première amélioration.

Merci,
Marc-André Dufour
MAD DevOps
```

## Réponse — offre terrain possible

```text

Merci pour les détails.

Voici ce que je comprends : [besoin en une phrase].

Je pense pouvoir vous aider avec [type d’aide simple], pour [friction à réduire].

La prochaine étape serait [action simple].

Merci,
Marc-André Dufour
MAD DevOps
```

## Réponse — suivi futur

```text
Bonjour [Nom],

Merci pour votre message.

Le besoin est intéressant, mais il semble préférable de le reprendre lorsque certains éléments seront plus clairs.

Je peux garder le contexte en note pour un suivi futur si pertinent.

Merci,
Marc-André Dufour
MAD DevOps
```

---

## Garde-fous

- Ne pas donner un prix trop tôt.
- Ne pas promettre une solution avant clarification.
- Ne pas utiliser de jargon technique inutile.
- Ne pas exposer la mécanique interne MAD DevOps.
- Garder une seule prochaine étape claire.
