# Exemple — Validation CHK-003 livraison client

## Objectif

Montrer comment valider une livraison client avec CHK-003 avant de l’envoyer ou de la présenter au client.

Cet exemple utilise le projet :

```text
Clarification du parcours de contact Web
```

## Livraison évaluée

| Élément | Valeur |
|---|---|
| Client | Client exemple — petite entreprise de services |
| Projet | Clarification du parcours de contact Web |
| Livraison | Parcours de contact clarifié et textes reformulés |
| Type | Amélioration ciblée site Web |
| Verdict CHK-003 | Livraison approuvée avec réserves mineures |

---

## 1. Besoin et périmètre

- [x] Le besoin initial est respecté.
- [x] Le périmètre livré correspond au mandat accepté.
- [x] Les éléments hors périmètre ne sont pas inclus par accident.
- [x] Les limites de la livraison sont visibles.

Résultat :

```text
Valide. La livraison reste limitée au parcours de contact et ne dérive pas vers une refonte complète du site.
```

---

## 2. Fonctionnement principal

- [x] Le parcours de contact est plus clair.
- [x] Les questions proposées aident à qualifier la demande.
- [x] Les textes sont compréhensibles par un visiteur non technique.
- [x] La prochaine étape est plus visible pour le visiteur.

Résultat :

```text
Valide. Le fonctionnement principal répond au problème initial : réduire les demandes floues.
```

---

## 3. Qualité et vérification

- [x] Les textes ont été relus.
- [x] Les ajustements simples sont cohérents avec le site existant.
- [x] Aucun changement non demandé n’a été ajouté.
- [x] Les éléments à confirmer sont nommés.

Résultat :

```text
Valide avec réserve mineure. Une validation finale du ton par le client reste souhaitable.
```

---

## 4. Sécurité, données et confidentialité

- [x] Aucune donnée sensible n’est exposée.
- [x] Aucune information client confidentielle n’est ajoutée dans les contenus publics.
- [x] Aucun accès client n’est documenté dans un contenu livrable.
- [x] Les accès utilisés restent privés.

Résultat :

```text
Valide. Aucun élément sensible n’est inclus dans la livraison.
```

---

## 5. Communication client

- [x] Ce qui est livré est résumé simplement.
- [x] Ce qui n’est pas inclus est clair.
- [x] Les réserves mineures sont nommées.
- [x] La prochaine action client est explicite.

Résultat :

```text
Valide. Le client peut comprendre ce qui a été amélioré et quoi valider ensuite.
```

---

## 6. Documentation et reprise

- [x] La fiche projet peut être mise à jour.
- [x] La décision de livraison est traçable.
- [x] Les TODO restantes sont visibles.
- [x] Une preuve client potentielle peut être évaluée après acceptation.

Résultat :

```text
Valide. La livraison peut être reliée au registre des preuves client seulement après acceptation et permission.
```

---

## Résultat de validation CHK-003

- [ ] Livraison approuvée
- [x] Livraison approuvée avec réserves mineures
- [ ] Livraison bloquée
- [ ] Livraison reportée

---

## Décision finale

```text
Décision : livraison approuvée avec réserves mineures.

Raison : le périmètre est respecté, le parcours de contact est clarifié et les risques majeurs sont absents. Le client doit encore valider le ton final des textes avant publication définitive.
```

---

## Prochaine action

```text
Envoyer la livraison au client avec un résumé clair et demander la validation du ton des textes proposés.
```

---

## Après acceptation

```text
1. Mettre à jour la fiche projet client.
2. Fermer les TODO restantes.
3. Identifier une preuve client potentielle.
4. Ne rien publier sans permission.
5. Utiliser CHK-030 si une preuve est préparée.
```
