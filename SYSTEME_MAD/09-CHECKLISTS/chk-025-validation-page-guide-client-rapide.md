# CHK-025 — Validation page Guide client rapide

## Objectif

Valider qu’une page de guide client rapide est claire, utile, simple et prête à orienter un visiteur vers la bonne prochaine étape.

Cette checklist évite de publier une page trop vague, trop longue ou trop centrée sur le système interne.

## Principe

```text
Une page d’orientation client doit aider le visiteur à se reconnaître et à choisir une prochaine étape simple.
```

---

## Checklist

### 1. Clarté client

- [ ] La page parle du besoin du visiteur avant de parler du système MAD.
- [ ] Les mots utilisés sont compréhensibles pour une personne non technique.
- [ ] Les situations présentées sont concrètes.
- [ ] La page ne ressemble pas à une documentation interne.

---

### 2. Orientation vers le bon besoin

- [ ] Les principaux types de besoins sont couverts.
- [ ] Chaque besoin mène à une orientation simple.
- [ ] Les options ne sont pas trop nombreuses.
- [ ] Le visiteur peut se reconnaître rapidement.

---

### 3. Prochaine étape

- [ ] La prochaine action est claire.
- [ ] Le visiteur sait quoi faire après la lecture.
- [ ] La page ne pousse pas une solution trop tôt.
- [ ] Le formulaire ou contact lié reste simple.

---

### 4. Garde-fous commerciaux

- [ ] Aucune promesse exagérée.
- [ ] Aucun jargon inutile.
- [ ] Aucun prix ou délai inventé.
- [ ] Aucune solution imposée avant qualification.
- [ ] Le ton reste humain et professionnel.

---

### 5. Raccordement système

- [ ] La page mène vers une demande entrante claire.
- [ ] Les demandes reçues peuvent être traitées avec les templates existants.
- [ ] L’offre terrain peut être utilisée après qualification.
- [ ] Le pipeline peut recevoir les opportunités pertinentes.

---

## Résultat de validation

- [ ] Page prête à publier
- [ ] Page à simplifier
- [ ] Page à clarifier
- [ ] Page à raccorder au formulaire/contact
- [ ] Page à retravailler

---

## Critères d’acceptation

La page est acceptée si :

1. elle parle clairement au visiteur;
2. elle aide à reconnaître un besoin;
3. elle propose une prochaine étape simple;
4. elle évite le jargon;
5. elle se raccorde au processus commercial MAD DevOps.
