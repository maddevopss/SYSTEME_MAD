# STD-605 — Documentation prête pour agents IA

## Règle d’or

Un agent IA ne devrait pas avoir à deviner quelle information est officielle.

---

## Objectif

Définir les règles qui rendent la documentation MAD DevOps utilisable par les agents IA sans amplifier la confusion.

---

## Règles obligatoires

- Indiquer clairement le statut du document.
- Donner un rôle explicite au document.
- Éviter les doublons actifs.
- Mentionner les documents associés lorsque nécessaire.
- Distinguer les règles, décisions, idées et archives.
- Écrire les consignes importantes de manière explicite.
- Ne pas cacher une décision importante uniquement dans une conversation.

---

## Bonnes pratiques

✔ Utiliser des titres précis.

✔ Ajouter une section “Objectif” ou “Rôle du document”.

✔ Mettre les documents de référence dans le manifeste.

✔ Garder les règles en listes claires.

✔ Signaler les limites et incertitudes.

✔ Garder les archives hors du chemin principal.

✔ Prévoir des checklists pour les tâches répétables.

---

## Anti-patterns

### Mauvais

Créer plusieurs documents similaires sans préciser la source officielle.

### Mauvais

Utiliser des formulations vagues comme “améliore tout ça” dans les documents de procédure.

### Mauvais

Laisser un agent choisir lui-même entre plusieurs versions contradictoires.

---

## Cas réel Système MAD

Avant de modifier le dépôt, un agent IA doit lire :

- `README.md`;
- `SYSTEME_MAD/MANIFEST.md`;
- `SYSTEME_MAD/00-SYSTEME-MAD/ai-context.md`;
- les standards applicables;
- les ADR applicables.
