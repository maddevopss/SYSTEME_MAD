# CHK-031 — Validation projet prêt à démarrer

## Objectif

Valider qu’un projet client est suffisamment clair pour passer du cadrage à l’exécution.

Cette checklist évite de commencer un mandat avec un périmètre flou, des accès manquants, des dépendances invisibles, des livrables ambigus ou des critères de réussite non définis.

## Principe

```text
Un projet est prêt à démarrer quand le prochain travail utile est clair, réalisable et cadré.
```

---

## 1. Besoin et problème réel

- [ ] Le problème principal est formulé clairement.
- [ ] L’impact du problème est compris.
- [ ] Le résultat souhaité est explicite.
- [ ] Le critère de réussite observable est défini.
- [ ] Le besoin n’est pas seulement une liste de fonctionnalités.

---

## 2. Périmètre et première version utile

- [ ] La première version utile est définie.
- [ ] Les éléments inclus sont listés.
- [ ] Les éléments hors périmètre sont visibles.
- [ ] Les demandes futures sont séparées du mandat actuel.
- [ ] Le client comprend ce qui ne sera pas livré maintenant.

---

## 3. Livrables

- [ ] Les livrables sont nommés.
- [ ] Chaque livrable a un statut initial.
- [ ] Les livrables sont compréhensibles par le client.
- [ ] La validation attendue pour chaque livrable est claire.
- [ ] La livraison finale peut être validée avec CHK-003.

---

## 4. Accès, contenus et dépendances

- [ ] Les accès requis sont identifiés.
- [ ] Les responsables des accès sont nommés.
- [ ] Les dates cibles sont visibles.
- [ ] L’impact d’un accès manquant est documenté.
- [ ] Les dépendances client sont visibles.
- [ ] Les dépendances techniques ou externes sont visibles.

---

## 5. Risques et blocages

- [ ] Les risques principaux sont identifiés.
- [ ] Les blocages potentiels sont visibles.
- [ ] Une action de réduction est prévue pour chaque risque important.
- [ ] Les accès bloquants ne sont pas ignorés.
- [ ] Les limites connues sont communiquées.

---

## 6. Décisions et changements

- [ ] Les décisions importantes sont documentées.
- [ ] Les changements de périmètre potentiels sont classés.
- [ ] Les demandes hors périmètre sont reportées, refusées ou à estimer.
- [ ] Les impacts sur délai, coût ou qualité sont visibles si pertinents.

---

## 7. Prochaine action

- [ ] Une TODO active existe.
- [ ] La prochaine action est claire.
- [ ] Le responsable de la prochaine action est identifiable.
- [ ] Le projet peut avancer sans réinterpréter tout le contexte.

---

## Résultat de validation

- [ ] Projet prêt à démarrer
- [ ] Projet prêt avec réserves
- [ ] Projet à clarifier avant démarrage
- [ ] Projet bloqué par accès ou dépendance
- [ ] Projet à recadrer

---

## Critères d’acceptation

Le projet est prêt à démarrer si :

1. le besoin est clair;
2. le périmètre est accepté;
3. les livrables sont visibles;
4. les accès critiques sont identifiés;
5. les risques principaux sont connus;
6. la prochaine action est claire.
