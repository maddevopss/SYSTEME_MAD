Gestion du code source

Règle d’or

Le code source est un patrimoine de l’entreprise.

Pourquoi ce chapitre existe

Le code représente les connaissances, les décisions et le travail investi dans une solution.

Il doit être protégé, organisé et traçable afin d’assurer sa pérennité.

Notre vision

Nous considérons le gestionnaire de versions comme la mémoire technique d’un projet.

Chaque modification importante doit pouvoir être comprise, retrouvée et justifiée.

Nos principes

* Chaque changement est traçable.
* Les historiques sont conservés.
* Les messages de commit sont clairs.
* Les branches ont un objectif précis.
* Les revues de code sont encouragées lorsque le contexte le permet.

Ce que nous faisons toujours

✔ Versionner le code.

✔ Décrire clairement les changements.

✔ Conserver un historique propre.

✔ Respecter les conventions établies.

Ce que nous évitons

✘ Modifier directement sans historique.

✘ Messages de commit imprécis.

✘ Mélanger plusieurs changements sans lien.

Citation

Le code évolue. Son histoire mérite d’être conservée.
