# DEC-003 — Reconnaissance officielle de BaseMAD

## Décision

BaseMAD est reconnue comme la couche centrale de continuité, mémoire opérationnelle et gouvernance documentaire du Système MAD.

Cette décision officialise BaseMAD comme mécanisme de transformation des idées, décisions, apprentissages, recherches, processus et modules produit en éléments structurés, retrouvables et réutilisables.

---

## Contexte

Le Système MAD contient maintenant plusieurs couches documentaires :

- fondations;
- standards;
- guides;
- playbooks;
- templates;
- checklists;
- roadmap;
- recherche;
- produit;
- modules MADSuite.

Sans couche centrale explicite, les idées importantes risquent de rester dispersées dans les conversations, les brouillons ou les documents non raccordés.

BaseMAD répond à ce besoin en donnant un cadre clair pour capter, classer, valider et raccorder ce qui doit survivre au changement de contexte.

---

## Justification

BaseMAD est nécessaire pour :

- préserver la continuité opérationnelle;
- réduire la perte d’idées utiles;
- éviter les décisions implicites;
- structurer la transformation d’une idée en élément utilisable;
- soutenir les modules produit comme MAD Ariane;
- améliorer la gouvernance documentaire;
- faciliter la reprise après interruption.

## Portée

Cette décision s’applique à tout le Système MAD.

Elle concerne notamment :

- les idées stratégiques;
- les décisions produit;
- les offres MAD DevOps;
- les méthodes internes;
- les modules MADSuite;
- les hypothèses R&D;
- les standards et checklists futures.

---

## Règles associées

Un élément important du Système MAD doit être :

- documenté;
- classé;
- raccordé;
- validable;
- retrouvable;
- révisable;
- aligné avec les standards existants.

Un élément ne doit pas entrer dans BaseMAD s’il est trop vague, non utile, non raccordé, duplicatif ou porteur d’une promesse non validée.

---

## Conséquences

À partir de cette décision :

- BaseMAD devient une couche officielle du Système MAD;
- les nouvelles idées importantes doivent être traitées via PLAY-025;
- les entrées significatives doivent être validées via CHK-018;
- les modules produit doivent être raccordés à BaseMAD lorsqu’ils deviennent structurants;
- les index doivent être mis à jour pour éviter l’invisibilité documentaire.

---

## Exemple de référence

MAD Ariane constitue un exemple complet de transformation BaseMAD :

```text
idée cognitive
→ recherche prudente
→ matrice de claims
→ MVP
→ spécification technique
→ lots d’implémentation
→ tests
→ checklist finale
→ index produit
```
