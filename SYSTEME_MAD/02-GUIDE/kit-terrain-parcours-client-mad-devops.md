# Kit terrain — Parcours client MAD DevOps

## Objectif

Ce kit sert à utiliser le parcours client MAD DevOps en situation réelle : premier échange, découverte, cadrage, proposition, livraison et suivi.

Il regroupe les repères opérationnels nécessaires pour savoir quoi dire, quoi décider, quoi confirmer et quand ralentir.

---

## ADN à garder en tête

```text
On ne vend pas du code.
On aide les gens à régler ce qui les ralentit.
```

---

## Règle de base

Ne jamais transformer une demande floue en promesse ferme.

- Si le besoin est flou : découverte ou cadrage.
- Si le besoin est clair : proposition.
- Si le risque est élevé : Phase 0.
- Si les attentes sont irréalistes : clarification, réduction ou refus.

---

## Chemin décisionnel rapide

1. Le problème réel est-il clair ?
2. Le résultat attendu est-il observable ?
3. Le périmètre est-il raisonnable ?
4. Les risques sont-ils acceptables ?
5. La prochaine action est-elle claire ?

Si une réponse est non, ralentir et cadrer.

---

## Repères terrain

| Situation | Réponse MAD DevOps |
|---|---|
| Le client ne sait pas par où commencer. | Faire une découverte. |
| Le besoin existe, mais le périmètre est incomplet. | Faire un cadrage. |
| Le projet est important ou risqué. | Proposer une Phase 0. |
| Le besoin est clair et raisonnable. | Préparer une proposition. |
| Le succès n’est pas observable. | Clarifier avant engagement. |
| Le client ajoute du périmètre. | Réévaluer ou mettre en phase future. |

---

## Suivis à produire

Après un premier échange : produire une synthèse courte avec problème, résultat souhaité, première version utile, questions ouvertes et prochaine action.

Après un cadrage : produire un cadrage validable avec périmètre, hors périmètre, risques et recommandation.

Avec une proposition : confirmer contexte, besoin, livrables, limites, responsabilités, échéancier et prochaine action.

Avant livraison : valider le périmètre livré, le parcours principal, les limites connues et la note de livraison.

Après livraison : confirmer ce qui est livré, les accès ou instructions, les limites connues et la suite recommandée.

---

## Contrôle qualité terrain

Avant d’avancer, vérifier :

```text
Le problème est-il clair ?
La prochaine action est-elle claire ?
Le client sait-il ce qui est inclus ?
Le client sait-il ce qui n’est pas inclus ?
Le succès est-il observable ?
Le risque principal est-il nommé ?
```
