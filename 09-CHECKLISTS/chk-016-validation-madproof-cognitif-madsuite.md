# CHK-016 — Validation MADPROOF cognitive MADSuite

## Objectif

Valider qu’une idée, fonctionnalité ou formulation cognitive MADSuite respecte le cadre MADPROOF, le positionnement non médical et les règles de prudence produit.

---

## Principe

```text
Inspirer la conception.
Limiter les claims.
Garder l’utilisateur en contrôle.
```

---

## Checklist

| Point de validation | Statut |
|---|---|
| L’idée est clairement classée : fondation, R&D, hypothèse ou fonctionnalité. | `[OK / À corriger]` |
| La formulation évite toute promesse médicale. | `[OK / À corriger]` |
| La formulation ne prétend pas lire un état mental. | `[OK / À corriger]` |
| Le bénéfice utilisateur est exprimé de manière prudente. | `[OK / À corriger]` |
| Les données nécessaires sont minimisées. | `[OK / À corriger]` |
| Le fonctionnement général peut être expliqué simplement. | `[OK / À corriger]` |
| L’utilisateur peut ignorer, ajuster ou désactiver l’aide. | `[OK / À corriger]` |
| La caméra est exclue du MVP par défaut. | `[OK / À corriger]` |
| Les limites du module sont nommées. | `[OK / À corriger]` |
| Une validation utilisateur est prévue avant claim externe fort. | `[OK / À corriger]` |
| Le document est relié à une note de recherche ou MADPROOF. | `[OK / À corriger]` |
| Les formulations interdites sont supprimées. | `[OK / À corriger]` |

## Usage recommandé

Utiliser cette checklist avant :

- ajout d’un module cognitif;
- rédaction d’un claim produit;
- publication d’une page MADSuite;
- test utilisateur;
- présentation externe;
- arbitrage MVP.
