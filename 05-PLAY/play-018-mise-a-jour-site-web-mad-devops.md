# PLAY-018 — Mise à jour site Web MAD DevOps

## Objectif

Mettre à jour le site Web MAD DevOps sans perdre la clarté, la simplicité et le positionnement officiel.

---

## Principe

```text
Comprendre vite.
Faire confiance.
Savoir quoi faire ensuite.
```

---

# 1. Lire les sources

Avant de modifier le site, lire :

```text
presence-web-mad-devops.md
message-site-web-mad-devops.md
communication-commerciale-mad-devops.md
offre-simple-mad-devops.md
```

---

# 2. Vérifier le message

La page doit répondre rapidement :

```text
Ce que MAD DevOps fait.
Pour qui.
Quel problème est aidé.
Quelle prochaine action poser.
```

---

# 3. Garder le langage simple

Éviter :

- jargon technique;
- longues listes de technologies;
- promesses exagérées;
- messages trop abstraits;
- pages trop chargées.

---

# 4. Vérifier les CTA

Chaque page importante doit proposer une prochaine action claire :

```text
Parler de votre besoin
Voir les façons de commencer
```

---

# 5. Valider avant publication

Avant de publier, vérifier :

- le message est clair;
- le ton est humain;
- les affirmations sont prudentes;
- la page est lisible sur mobile;
- la prochaine action est visible;
- le contenu reste cohérent avec la mission.
